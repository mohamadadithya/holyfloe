# Fixtures: the executable spec

Write these Lit components by hand in `fixtures/src/<name>/` BEFORE any emitter. Each has its own `custom-elements.json` (generated by the analyzer, committed) and hand-written expected output in `fixtures/expected/<framework>/<name>/`. Snapshots in the Rust crates must agree with `expected/` after review.

Layout

```
fixtures/
  src/<name>/<name>.ts
  src/<name>/custom-elements.json
  expected/react/<name>/...
  expected/vue/<name>/...
  expected/svelte/<name>/...
  out/                         # generated by `just gen-fixtures`, compared against expected/
```

## Expected output rules

- Hand-write expected output for fixture 1 first, for React only. Get it reviewed. It sets the style for everything else.
- Expected files are what a human would be happy to see in a design system repo: formatted, commented, no generator noise except one header line `// Generated by holyfloe. Do not edit.`
- Never edit `expected/` to make a test pass without recording why in the commit message.

## Consumer tests (type-level)

For each framework and each fixture, add `fixtures/consumers/<framework>/<name>.(tsx|vue|svelte)` that:
1. Uses the generated component with correct props, events and slots. Must compile.
2. Has a sibling `<name>.fail.(tsx|vue|svelte)` with `@ts-expect-error` cases (wrong prop type, wrong detail type). Must produce exactly those errors.

## Conformance e2e

`e2e/<app>` renders every fixture. Port the categories of Custom Elements Everywhere: primitive and complex props, boolean attributes, and events named lowercase / kebab / camel / uppercase / Pascal. Each wrapper is scored on the same list.
