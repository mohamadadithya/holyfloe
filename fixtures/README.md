# Fixtures: the executable spec

Write these Lit components by hand in `fixtures/src/<name>/` BEFORE any emitter. Each has its own `custom-elements.json` (generated by the analyzer, committed) and hand-written expected output in `fixtures/expected/<framework>/<name>/`. Snapshots in the Rust crates must agree with `expected/` after review.

Layout

```
fixtures/
  src/<name>/<name>.ts
  src/<name>/custom-elements.json
  expected/react/<name>/...
  expected/react-types/<name>/...     # React `types` mode (React 19 only)
  expected/react-ref-prop/fx-button/  # `react.ref: "prop"` (React 19 only), config holyfloe.ref-prop.config.json
  expected/vue/<name>/...
  expected/svelte/<name>/...
  out/                         # generated by `just gen-fixtures` (committed), compared against expected/
  dist/                        # `just build-fixtures` (tsc), git-ignored; package `exports` point here (D-053)
  holyfloe.config.json         # shared config: `moduleRewrite: {"src/": "dist/"}`
  consumers/react{,-types,-ref-prop}/, consumers/vue/, consumers/svelte/  # consumer tests per output, see below
  typecheck/react18, react19/  # pinned @types/react; `just typecheck-react` runs tsc --strict in each
  typecheck/vue, svelte/       # vue-tsc and svelte-check --fail-on-warnings, on TypeScript 6 (D-071)
  custom-elements-manifest.config.mjs  # analyzer config, uses `@holyfloe/core/cem-plugin` (`@model` -> `x-holyfloe-models`, D-063)
```

Each fixture's Lit source is also the input for `holyfloe-lit`: `just parity` builds the IR from `src/<name>/*.ts` and from the committed `custom-elements.json` and requires them equal (D-089).

All 12 have expected output for React, Vue and Svelte (M2 done). A fixture that needs its own config (fx-events: event-name overrides; fx-select: a config binding) has `src/<name>/holyfloe.config.json`; the others use `fixtures/holyfloe.config.json`. Overrides for tags missing from a manifest are an error (`E009`), so they cannot live in the shared file.

## Expected output rules

- Hand-write expected output for fixture 1 first, for React only. Get it reviewed. It sets the style for everything else.
- Expected files are what a human would be happy to see in a design system repo: formatted, commented, no generator noise except one header line `// Generated by holyfloe. Do not edit.`
- Never edit `expected/` to make a test pass without recording why in the commit message.

## Consumer tests (type-level)

For each framework and each fixture, add `fixtures/consumers/<framework>/<name>.(tsx|vue|svelte)` that:
1. Uses the generated component with correct props, events and slots. Must compile.
2. Has a sibling `<name>.fail.(tsx|vue|svelte)` with `@ts-expect-error` cases (wrong prop type, wrong detail type). Must produce exactly those errors. Vue uses `@vue-expect-error` in templates; svelte-check has no expect-error for markup, so Svelte fail files check props objects (`ComponentProps<typeof X>`).
3. Raw tags (the `global-components.d.ts` / `svelte-elements.d.ts` augmentations) are tested in `raw-tags{,.fail}.(vue|svelte)`, which import no wrapper: in Vue, `<fx-input>` in a file that imports `FxInput` is the wrapper. Every Svelte consumer has `<script lang="ts">`, because svelte-check only type-checks markup in TypeScript components (D-080).

## Conformance e2e

`e2e/<app>` renders every fixture. Port the categories of Custom Elements Everywhere: primitive and complex props, boolean attributes, and events named lowercase / kebab / camel / uppercase / Pascal. Each wrapper is scored on the same list.
