# holyfloe: Lit to React / Vue / Svelte wrapper engine

Rust engine that reads Custom Elements Manifest (CEM) data for Lit web components and generates idiomatic, typed wrappers for React, Vue 3 and Svelte 5.

**Current state: pre-M0.** Only `docs/` and `fixtures/README.md` exist. There is no Cargo workspace, no `justfile`, no fixtures, and the directory is not yet a git repo (run `git init` before the first commit). Everything under "Workspace layout" and "Commands" is the target, not what's on disk.

## Pipeline (big picture)

```
custom-elements.json (from @custom-elements-manifest/analyzer --litelement)
  -> holyfloe-cem   serde types (typify, checked in)
  -> holyfloe-ir    Library/Component IR + 6 passes in fixed order:
                    flatten-inheritance -> drop-non-public -> name-derive
                    -> classify-props -> infer-bindings -> validate
  -> holyfloe-emit-{react,vue,svelte,types}   minijinja templates -> Vec<OutputFile>
  -> holyfloe-fs    plan + hash + write-if-changed (only place that touches disk,
                    along with holyfloe-cli and holyfloe-napi)
```

Emitters read only the IR, never CEM (D-011). Things CEM doesn't model (`PropKind`, `TwoWayBinding`, `form_associated`, derived event prop names) are computed in IR passes, so all three frameworks share them. `PropKind` decides SSR attribute vs. client property handling in every emitter.

Fixtures are the spec: `fixtures/src/<name>/` (Lit source + committed CEM) -> `fixtures/expected/<framework>/<name>/` (hand-written) and `fixtures/out/` (generated, must match). `fixtures/consumers/` holds type-level compile and `.fail` tests.

## Workspace layout

```
crates/
  holyfloe-cem/        # serde types for CEM 2.1.0 (typify-generated, checked in, never regenerated in build.rs)
  holyfloe-ir/         # IR structs + normalization passes. Pure, no I/O.
  holyfloe-lit/        # M4 only: oxc-based Lit extractor -> IR. Feature-gated.
  holyfloe-emit-core/  # minijinja env, shared filters (pascal/camel/kebab, ts-escape, jsdoc)
  holyfloe-emit-react/
  holyfloe-emit-vue/
  holyfloe-emit-svelte/
  holyfloe-emit-types/ # JSX / Vue / Svelte global type augmentation
  holyfloe-fs/         # output planning, content hashing, write-if-changed
  holyfloe-cli/        # clap + notify
  holyfloe-napi/       # napi-rs v3 bindings
packages/
  core/             # npm wrapper around napi binaries
  unplugin/         # unplugin factory calling core
fixtures/           # Lit component corpus + expected outputs (the spec)
e2e/                # react18/ react19/ next-app/ vue3/ nuxt/ svelte5/ sveltekit/
```

## Hard rules

- **Pure core.** IR and emitters are `fn(&Ir, &Config) -> Vec<OutputFile>`. No filesystem, network, or clock access outside `holyfloe-fs`, `holyfloe-cli`, `holyfloe-napi`.
- **Never resolve types.** Keep type text verbatim from the CEM. Emit `import type { El } from '<pkg>/<module>'` and derive prop types as `El['prop']`. Do not add a TypeScript checker dependency.
- **Templates, not ASTs,** for framework files (`.svelte`, `.vue`, `.tsx`, `.d.ts`). Use minijinja. One template directory per framework.
- **Snapshots are the spec.** Every emitter x every fixture has an insta snapshot. Never accept a snapshot change without saying why.
- **No unwrap/expect in library crates.** Return typed errors (`thiserror`). The CLI may print and exit.
- **Pin exact versions** of oxc, minijinja, typify, napi. Upgrade only in a dedicated PR.
- **Generated TypeScript must type-check** with `strict: true`.
- **Do not copy wc-toolkit code.** Port output shapes, write original code.

## Commands (created in M0; if missing, create them first)

```
cargo build --workspace
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
cargo insta review                      # review snapshot changes
just gen-fixtures                       # regenerate fixtures/out from fixtures/src
just typecheck                          # tsc / vue-tsc / svelte-check on fixtures/out
just e2e                                # Playwright matrix in e2e/
just verify                             # all of the above, in order
```

Focused variants named in the roadmap exit commands (create them along with the `justfile`):

```
cargo test -p holyfloe-ir <test_name>   # single test in one crate
cargo insta test -p holyfloe-emit-react # run one emitter's snapshots, then `cargo insta review`
just gen-fixtures-cem                   # run the CEM analyzer over fixtures/src (M0)
just typecheck-react | typecheck-vue | typecheck-svelte
just e2e-react | e2e-vue | e2e-svelte
just parity                             # M4: oxc IR == analyzer IR on every fixture
pnpm -C packages/core test              # M3
pnpm -C packages/unplugin test          # M3
```
